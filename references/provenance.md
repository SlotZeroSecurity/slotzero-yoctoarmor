# Provenance and review boundaries

This package contains self-sufficient NEAR security rules, source hashes, and historical disposition ledgers. No external document is needed during an audit. A source instance is precedent, never evidence that the audited target is vulnerable. All target findings require a reachable path, broken invariant, and material target-specific harm.

The current review identified changes to NEP-393 and NEP-616 and added Draft NEP-652. The seven category checklists contain distilled rules, not copied standards text.
- The documentation registry is pinned to `near/docs@117e74217efdf921cf55da6b5e0b0e3f622bc4db`. Its 197 discovered page and OpenAPI records are individually hashed and classified in `official-docs-registry.json`. The review added the callback-failure and integration pages to relevant card routes.
- Final and Approved NEP requirements are normative only when the target implements or claims the applicable interface and its version/feature gate is active. Draft and New material is advisory. NEP-21 is a legacy trigger only when the target uses it; NEP-1 is process-only. Every excluded registry item receives a target-specific reason in the coverage ledger. The registry size is an inventory result, not a fixed audit scope or vulnerability count.
- Official docs clarify runtime behavior but are not themselves conformance standards. In particular, a callback runs after a failed callee but can itself fail; the callback receipt's changes then revert while earlier receipt effects remain. A failed callback does not schedule a refund that it would have created. This underlies the local async-settlement cards.

## Taxonomy and isolation

`attack-lenses-index.json` routes ten category files. Every card has one permanent `NA-<CATEGORY>-NNN` ID; new audit outputs use only these IDs. `historical-id-map.json` is the sole old-ID translation record, including the 56 earlier canonical patterns and 39 portable keys. Quality-only cards retain source accounting but are not security findings absent independently proven harm.

L0 and L2 are corpus-blind. Blind L3 and standards-only workers receive no source ledger or attack-lens corpus. Only L1 and the post-blind echo receive target-selected categories, then consult selected source variants after binding a mechanism to the target. The controller records this as instruction-level isolation unless the host supplies stronger enforcement evidence.

Reference and script changes alter the configuration hash. Old runs remain bound to the original installed package or must restart under this redesign. No benchmark-detection or recall claim follows from the package's regression or smoke tests.
